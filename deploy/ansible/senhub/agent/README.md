# Ansible collection senhub.agent

Installs the [SenHub Agent](https://github.com/senhub-io/senhub-agent),
writes its multi-file configuration and checks that configuration with
`senhub-agent config check --json` before it replaces the live files.

| Target | How the agent is installed |
|---|---|
| Debian, Ubuntu | Signed APT repository at `packages.senhub.io` |
| RHEL, Rocky, AlmaLinux, Fedora | Signed YUM/DNF repository |
| openSUSE, SLES | Signed Zypper repository (written, not yet run) |
| Windows | MSI found through the release manifest, SHA-256 checked (written, not yet run) |

The user guide page is `docs/user-guide/docs/ansible.md` of the agent's
repository, published as "Deploying with Ansible".

## Install

```bash
ansible-galaxy collection install senhub.agent
```

Or from the repository:

```bash
ansible-galaxy collection install git+https://github.com/senhub-io/senhub-agent.git#/deploy/ansible/senhub/agent,master
```

Requires `ansible-core` 2.15 or later, and the collections `community.general`
(Zypper) and `ansible.windows` (Windows hosts), which Galaxy installs with it.

## Use

```yaml
- hosts: monitored
  become: true
  roles:
    - role: senhub.agent.agent
      vars:
        senhub_agent_edition: oss
        senhub_agent_channel: stable
        senhub_agent_probes:
          - {name: cpu-fast, type: cpu, params: {interval: 15}}
        senhub_agent_strategies:
          otlp: {endpoint: "collector.example.com:4317"}
```

`senhub_agent_state: absent` removes the agent. Every variable is described
in `roles/agent/defaults/main.yml` and in the user guide.

The licence of a paid edition goes in a vault variable:

```yaml
senhub_agent_edition: full
senhub_agent_license: "{{ vault_senhub_licence }}"
```

## Behaviour worth knowing

- The configuration is built in a scratch copy of the live directory and
  checked there. A check that exits 2 (or 1, unless
  `senhub_agent_check_allow_warnings` is true) fails the play and changes
  nothing on the host.
- The agent loads changes to `agent.yaml`, `probes.d/` and `strategies.d/`
  by itself, so the role restarts the service only for a new licence (read
  at start), a package switch, or when `senhub_agent_restart_on_config_change`
  is true. The role has no "reload" handler because the agent has no reload
  command or signal.
- Fragments the role writes carry a `# Managed by Ansible (senhub.agent)`
  line. Only files with it are removed when they are no longer declared; a
  fragment you wrote by hand is never touched.
- The agent key of the host is generated by the package and is never
  overwritten.
- The secrets of probe parameters belong in `${file:...}`, `${env:...}` or
  the agent's secret store. Values written inline are in the fragment, mode
  `0600`, owned by the service user.
