# 0.5.6 — 2026-09-19

A patch for the container image: the Azure Container Apps shortcut follows
several applications from one collector, instead of one.

<div class="rn-filter"></div>

## Features

- **`SENHUB_AZURE_APP` takes a list.** Following more than one Container App
  from one collector meant writing the whole probe array by hand into
  `SENHUB_PROBES`, with the five credential references repeated per entry and
  a distinct bookmark path to remember. The variable now accepts names
  separated by commas and writes one probe instance per name, each with its
  own bookmark:

    ```yaml
    SENHUB_AZURE_APP: "oltp,billing,web"
    ```

    The applications of one list share the credentials, the subscription and
    the resource group, since each of those is a single variable. Spaces
    around a name are absorbed, a name given twice is declared once, and a
    name that is not a Container App name stops the container rather than
    being written through.

- **The two doors say when they collide.** `SENHUB_AZURE_APP` and
  `SENHUB_PROBES` write two different files and are not merged, so an
  application named in both was declared twice and every line of it left
  twice, with nothing saying so. The entrypoint now reports it at startup
  when both variables are set. It is a message, not a refusal: naming
  different applications in each is legitimate.

Nothing else changes. The agent binary is identical to 0.5.5; only the
container image's entrypoint and the documentation differ.
