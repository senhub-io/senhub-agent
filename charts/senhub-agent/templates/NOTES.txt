{{- $ds := eq (include "senhub-agent.kind" .) "DaemonSet" }}
SenHub Agent {{ include "senhub-agent.imageTag" . }} ({{ .Values.edition }} edition) is deployed as
{{ .Release.Namespace }}/{{ include "senhub-agent.fullname" . }}, {{ if $ds }}a DaemonSet: one agent per node{{ else }}one pod{{ end }}.

Watch it start (the entrypoint says which configuration it wrote):
  kubectl -n {{ .Release.Namespace }} logs {{ include "senhub-agent.kind" . | lower | replace "daemonset" "ds" | replace "deployment" "deploy" }}/{{ include "senhub-agent.fullname" . }} -c agent -f

{{- if $ds }}
Each node's agent has its own identity: the agent key is generated at its first
start and kept in {{ .Values.daemonSet.stateHostPath }} on that node (agent.key), and the host id is the
node's machine-id. Read a node's key, for PRTG or Nagios, through its pod:
  kubectl -n {{ .Release.Namespace }} exec ds/{{ include "senhub-agent.fullname" . }} -c agent -- cat /var/lib/senhub-agent/agent.key
(ds/ picks one pod; use `kubectl get pods -o wide` and `exec <pod>` for a given node.)
Each agent's HTTP output is on its node: http://<node address>:{{ .Values.http.port }}. There is no Service.
{{- else }}
Its identity lives in the Secret {{ include "senhub-agent.identitySecretName" . }}
(host-id, agent-key){{ if not .Values.identity.existingSecret }}, kept after helm uninstall{{ end }}. Read the agent key,
which PRTG, Nagios and a Prometheus scrape authenticate with:
  kubectl -n {{ .Release.Namespace }} get secret {{ include "senhub-agent.identitySecretName" . }} -o jsonpath='{.data.agent-key}' | base64 -d; echo
{{- if and (not .Values.identity.existingSecret) (not .Values.identity.hostId) }}

Rendering with `helm template` (Argo CD, Flux with post-rendering) cannot read that
Secret and mints a new identity at each render: set identity.hostId and
identity.agentKey, or identity.existingSecret, under such a tool.
{{- end }}
{{- if .Values.service.enabled }}

Reach the HTTP output (console, PRTG, Nagios, Prometheus):
  kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "senhub-agent.fullname" . }} {{ .Values.service.port }}:{{ .Values.service.port }}
  curl http://127.0.0.1:{{ .Values.service.port }}/health
Inside the cluster: http://{{ include "senhub-agent.fullname" . }}.{{ .Release.Namespace }}.svc:{{ .Values.service.port }}
{{- end }}
{{- end }}
{{- if and .Values.kubernetesProbe.enabled (not .Values.rbac.kubernetesProbe.enabled) (not (get .Values.kubernetesProbe.params "kubeconfig")) }}

WARNING: kubernetesProbe.enabled reads this cluster through the pod's service
account, but rbac.kubernetesProbe.enabled is false: every collector will be
refused. Set rbac.kubernetesProbe.enabled=true, or give the probe a kubeconfig.
{{- end }}
{{- if and (eq .Values.edition "full") (not .Values.secrets.existingSecret) (not (hasKey .Values.secrets.values "SENHUB_LICENSE")) }}

No SENHUB_LICENSE in secrets.values: the licensed probes stay off (Free tier),
unless the Secret given as secrets.existingSecret carries one.
{{- end }}
{{- if $ds }}

The state stays on each node after helm uninstall. Remove it on every node to start over:
  sudo rm -rf {{ .Values.daemonSet.stateHostPath }}
The agents run on the nodes the tolerations and nodeSelector allow: by default not the
control-plane nodes (their NoSchedule taint); see `tolerations`.
{{- end }}
{{- if .Values.hostMonitoring.enabled }}

hostMonitoring.enabled: the pods run in the node's PID and network namespaces
and mount the node's root filesystem read-only at {{ .Values.hostMonitoring.hostRoot }}. Each watches its node
(with a Deployment, the node it was scheduled on: use nodeSelector), and the namespace must allow
the `privileged` Pod Security level:
  kubectl label namespace {{ .Release.Namespace }} pod-security.kubernetes.io/enforce=privileged
Port {{ .Values.http.port }} is opened on the node itself.
{{- else }}

hostMonitoring.enabled is false: disks, the network interface and processes are
the pod's own; CPU and memory are still the node's (/proc is not isolated).
{{- end }}
{{- if and .Values.persistence.enabled (not $ds) }}

The state volume {{ include "senhub-agent.fullname" . }}-state and the Secret {{ include "senhub-agent.identitySecretName" . }} are kept by
helm uninstall. Delete them to start over:
  kubectl -n {{ .Release.Namespace }} delete pvc {{ include "senhub-agent.fullname" . }}-state
{{- end }}
{{- if .Values.config.agent }}

config.agent is set: the configuration is yours, and every `env` value is ignored.
{{- end }}
